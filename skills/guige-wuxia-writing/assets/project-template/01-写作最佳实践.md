# 鬼哥武侠写作最佳实践

这份文档说明怎样把 `$guige-wuxia-writing` 当作一套长期创作系统使用，而不只是让 AI 临时生成一段“古风文字”。若只想马上开始，请先看 [00-使用指南.md](00-使用指南.md)；需要规划全书、稳定人物、连续写章或系统修稿时，再使用本手册。

## 一、这套 skill 解决什么问题

这套 skill 的目标，是帮助你创作具有原创人物、原创世界与独立表达的中文武侠或历史冒险小说，同时吸收传统武侠中可迁移的叙事方法：人物驱动、义务冲突、伸缩视角、清楚的语块句法、鲜明声口、文化质感与可诵读节奏。

它不是：

- 某位作家的句子仿写器；
- 古词、成语、四字格和说书套语生成器；
- 输入一句梗概便自动完成整部长篇的黑箱；
- 只负责润色、却不管理因果与连续性的文风插件。

它更接近三种角色的组合：

```text
故事编辑：检查人物选择、因果、信息和章节职责
共同作者：按既定人物、视角和场景目标创作正文
项目管理员：维护关系、时间、认知、物件、命名与素材状态
```

最佳效果来自一个循环：

```text
讨论方案 → 确认设定 → 规划场景 → 创作正文 → 审校 → 同步项目状态
```

## 二、完整能力地图

### 1. 故事与篇章层

| 方面 | 具体写作手法 | 主要解决的问题 |
|---|---|---|
| 人物驱动 | 稳定天性在不同利益下反复受考验；优点同时带来能力、盲点和代价 | 情节很多，人物却没有生命力 |
| 义务冲突 | 给人物两项都有正当来源、却无法同时履行的责任 | 冲突只有好坏选边，没有真正两难 |
| 因果推进 | 目标—阻力—选择—不可逆变化—新问题 | 事件靠作者强推，章节结束后自动复位 |
| 场景压力 | 空间限制、身体限制、信息差、失败代价与新入场者共同施压 | 场景松散，人物随时可以离开或求援 |
| 多线合流 | 每场同时推进事件、关系、信息、能力或道德选择中的至少两项 | 场景只负责说明资料 |
| 历史私人化 | 公共历史进入姓名、遗物、家训、阵营和私人关系 | 历史只是背景板 |
| 张弛组织 | 在危险、诙谐、亲近、掌故、新线索与公共冲突之间换味 | 全书始终高压或机械一紧一松 |
| 章节牵引 | 用迫近危险、关系裂缝、未解信息或两难选择收束 | 章末只会突然袭击 |

### 2. 叙述与认知层

| 方面 | 具体写作手法 | 主要解决的问题 |
|---|---|---|
| 视角伸缩 | 外部动作—贴身感知—人物判断—短促心语—返回动作 | 全知解释过多，或限知视角僵硬 |
| 安全换焦 | 一个节拍只进一人内心；换焦前先写新人姓名、感知或动作 | 多人物场面无锚点跳心 |
| 事实分层 | 区分客观事实、人物感知、人物解释、公开说法与读者认知 | 人物知道不该知道的事，悬念不公平 |
| 合理误判 | 两条以上真实证据加人物盲点、愿望或恐惧，形成最经济的错误解释 | 靠人物突然变笨制造误会 |
| 线索生命周期 | 植入—注意—解释—变义—证明—后果 | 伏笔只埋不收，或谜底靠新证据空降 |
| 揭示阶梯 | 异常—假设—支持—裂缝—重构—证明—公开—代价 | 一次性倾倒谜底，揭示后局面不变 |
| 读者位置 | 明确读者领先、同步、落后或与多人错位 | 悬念、惊奇与反讽混在一起 |

### 3. 人物与关系层

| 方面 | 具体写作手法 | 主要解决的问题 |
|---|---|---|
| 专属声口 | 注意力偏好、知识边界、关系语域、说话策略与压力变形共同生成台词 | 所有人都说同一种漂亮古风话 |
| 对白行动化 | 每句话执行试探、说服、拖延、威胁、隐瞒、拒绝或交换 | 对白只是给读者讲设定 |
| 称谓动作 | 称谓的抬高、降格、恢复与撤回显示关系变化 | 称呼固定不变，亲疏只靠旁白说明 |
| 情感显影 | 触发—截停—掩饰—泄漏—识别—选择—余波 | 直接写“很悲伤、很感动” |
| 情感通道 | 从身体、对白、称谓、关系动作、物件、环境、错误行动和短心语中择取 | 人人轮流低头、咬唇、攥拳、落泪 |
| 延迟释放 | 人物先完成职责，安全后才允许情绪释放 | 强烈情感一律立即哭喊 |
| 人物诙谐 | 字面错位、框架改写、身份与欲望反差、自嘲、重复变奏等 | 笑话可以搬到任何人物与场景 |
| 情绪换挡 | 基准主调—异调信号—现场铰链—表达变速—新调接管—旧调余味 | “气氛忽然严肃”式生硬转调 |

### 4. 世界、文化、物件与命名层

| 方面 | 具体写作手法 | 主要解决的问题 |
|---|---|---|
| 文化织入 | 历史种子化、典故动作化、知识交锋、风俗剧情化、地域具身化、礼俗契约化 | 典故与风物成为百科插页 |
| 真实性分层 | 区分史实、争议、传说、文学表达、艺术加工与纯虚构 | 把传说写成确定史实 |
| 人物文化边界 | 不同出身的人分别知道、误解、曲解或实用化不同材料 | 所有人同样博学 |
| 物件生命周期 | 落地—辨识—附着—转手—变质—潜伏—重现—清账 | 道具需要时瞬移，损伤自动复原 |
| 权属拆分 | 分开实际持有人、正当所有者、合格使用者与公开承认者 | 拿到令牌便自动合法 |
| 延迟因果 | 已建立的物理规则加中途状态变化，再由人物选择触发后果 | 结尾突然增加道具属性 |
| 知识载体 | 分开拥有、看见、读懂、训练、应用与形成判断 | 得到秘本便立即升级 |
| 命名权 | 先确定谁命名、为何命名、谁接受或拒绝这个名称 | 所有专名都像同一作者随机拼字 |
| 语义网络 | 人物、门派、武学、器物、地点和章名共享生活与文化词源 | 各名称孤立、只有“古雅”共同点 |
| 机制命名 | 先设计动作、材料、地形与用途，再反推名称 | 招式换名不换动作 |
| 名称变义 | 本名、绰号、旧称和章名由后续行动证明、反讽或重写 | 名字只是一次性标签 |

### 5. 句子与声音层

| 方面 | 具体写作手法 | 主要解决的问题 |
|---|---|---|
| 十二类句式 | 景物、登场、外貌、身体反应、心理判断、日常动作、武打、对白、镜头引导、突发、因果揭示、段落收束 | 不同内容都写成同一种句子 |
| 语块组织 | 用主体、动作、状态、判断、转折和结果等意义块组成长句 | 长句缠绕，短句零碎 |
| 连接词开关 | 分别控制镜头、感官、时间、预期、心理、因果、回应与收束 | “只见、当下、原来”沦为古风装饰 |
| 基础节奏 | 三拍、四拍、判断—行动、长铺短断、快速连击、递进复现 | 全段等长、同速、同构 |
| 诵读声音 | 安排轻重拍、内容重音、句法复现、对白轮次、破拍和具体收音 | 文字看着华丽，念起来拗口 |
| 动作落点 | 句尾落在方向、接触、停止、结果或状态变化 | 连续用抽象情绪和评价收尾 |
| 朗读编辑 | 切语块、标重音、查轻拍、看句尾、实际朗读与盲听 | 只在屏幕上修改，不检查口腔节奏 |
| 伪腔清理 | 删除无功能古词、四字格、套语、口头禅、拟声与解释尾巴 | 只有“像”，没有清楚与真实 |

这些层不是每场都要全部打开。规划长篇时重故事、信息和状态；写正文时重视角、人物、情感和语句；专项修稿时只调用当前问题所需的模块。

## 三、最重要的使用原则

### 1. 先让故事成立，再让句子好听

若人物没有目标、阻力和选择，继续增加古雅词汇不会使场景成立。正确顺序是：

```text
因果与选择 → 视角与信息 → 人物与关系 → 句法与声音
```

### 2. 把“讨论方案”与“确认入库”分开

头脑风暴中的方案不是作品事实。探索时明确说：

```text
先讨论，给我三个方向，不要写正文，也不要把未确认方案写入项目档案。
```

确认后再说：

```text
采用方案二。请更新相关项目文件，并列出本次确立的设定。
```

### 3. 每次只给 AI 一个清楚的主任务

“设计人物并写十章再全面润色”会让各层互相污染。更可靠的拆分是：

```text
故事核心 → 主要人物 → 总纲 → 下一章 → 当前场景 → 正文 → 同步
```

### 4. 不要求 AI 每次读取所有资料

项目越长，全文加载越容易冲淡当前任务。告诉 AI 当前目录是小说项目、当前任务是什么即可；skill 会按任务选择人物卡、章节计划、知识账本、物件账本或素材清单。

### 5. 重要变化必须回写

正文写完不等于工作结束。至少同步：

- 时间、地点、行程和伤势；
- 人物新知、误信与秘密公开范围；
- 关系、称谓和承诺变化；
- 物件位置、持有人、损伤与用途；
- 新专名、异名和语义关系；
- 新伏笔、已回收问题与下一章义务。

### 6. 技巧服从当前戏剧任务

文化、幽默、物件、命名和声音都不是必填项。若某项技巧不改变行动、关系、信息、风险或读者感受，就不应为了显示风格强行加入。

## 四、从零开始一部作品

### 阶段一：确定核心命题

先完成 `premise.md`：

- 主角想得到什么；
- 什么力量阻止他；
- 他面对哪两项都合理、却不能同时满足的义务；
- 读者将持续获得怎样的类型体验；
- 作品讨论什么问题；
- 与参考作品保持哪些原创边界。

推荐请求：

```text
使用 $guige-wuxia-writing，以当前目录为小说项目。一次只问我一个问题，帮助我确定一句话故事、类型承诺、主题问题和核心义务冲突。先讨论，确认后更新 `premise.md`。
```

### 阶段二：建立世界的压力与生活

填写 `world.md` 时，不急着编百科。优先确定：

- 权力、江湖与官府怎样真实影响人物；
- 地貌、交通、生产和物价怎样限制行动；
- 礼俗、师承、婚丧与名分怎样建立义务；
- 武学能做什么、不能做什么；
- 史实、传说与虚构怎样分层；
- 不同共同体分别怎样命名。

### 阶段三：建立主要人物系统

每位核心人物至少明确：

```text
欲望与深层需要
稳定天性及其代价
两难义务与底线
已知、误信与盲点
专属声口和关系语域
专属情感泄漏方式
诙谐机制与严肃触发点
关键选择链
```

不要一次创造二十个人。先完成会互相施压的三至五位核心人物，再随故事需要扩展。

### 阶段四：建立命名、物件和文化支撑

这三项应从已有世界与人物反推：

- 在 `naming-system.md` 建立核心阵营的二至四个语义场；
- 在 `objects-and-clues.md` 只登记会跨场景保存状态的重要物件；
- 在 `materials/candidates.md` 暂存模型知识、用户记忆和搜索所得的库外候选；
- 核验后在 `materials/` 建立独立素材卡，记录来源、适用边界和叙事用途；
- 在 `reference-manifest.md` 只登记已经确认用于故事的文化材料。

项目素材库是可靠锚点，不是 AI 的知识白名单。允许继续提出库外候选，但具体史实未经核验不得进入正式设定。不要先制造大量招式名、宝物和典故，再寻找情节安放它们。

### 阶段五：设计总纲

在 `story-outline.md` 中用“选择链”而非“事件列表”规划：

```text
人物阶段目标
→ 外部与内部阻力
→ 有代价的关键选择
→ 不可逆变化
→ 新的问题与更难义务
```

同时规划：

- 秘密、误判与揭示的阶段进展；
- 关系、称谓和情感债务的变化；
- 核心物件的转手、变质与回收；
- 语气的张弛和早期笑点的后期变义；
- 公共历史怎样逐步压到私人命运。

总纲不必把每章写死，但必须知道主要因果与结局方向。

## 五、一章的标准生产流程

### 第一步：先规划章节职责

从 `chapter-plans/chapter-plan.md` 复制一份，明确：

- 本章推进哪条主线；
- 谁想得到什么；
- 场景链怎样逐步增加压力；
- 哪个选择造成章末不可逆变化；
- 信息、关系、语气、物件和命名有哪些变化；
- 章名抓取什么具体锚点，而不是怎样总结全章。

### 第二步：只载入相关状态

正文开写前核对：

```text
当前章节计划
在场人物卡与相互关系
故事前一刻的时间、位置与伤势
本场相关的秘密、线索和人物认知
本场会触碰的物件及其状态
实际使用的文化素材
```

### 第三步：分场创作

长章优先逐场完成。每场写清目标、阻力和结束状态，再写下一场；这样更容易守住视角、知识权限和节奏。

### 第四步：做专项审校

不要只要求“全面润色”。按收益选择一至三项：

- 视角与信息公平性；
- 人物声口与对白策略；
- 情感潜台词；
- 武打的空间、受力与局势变化；
- 文化素材是否真正入戏；
- 语块、连接词与诵读节奏；
- 伪古风与解释尾巴清理。

### 第五步：同步章节后状态

推荐请求：

```text
把本章当作已确认正文，回放所有状态变化。更新人物认知、关系与称谓、时间行程与伤势、物件位置与状态、专名登记、伏笔和问题栈；只更新实际发生的内容，并给我一份简短同步摘要。
```

## 六、一场戏的三遍写作法

### 第一遍：让场景成立

先回答：

1. 谁是感知中心？
2. 他眼前想得到什么？
3. 谁或什么阻止他？
4. 哪两种力量或义务互相冲突？
5. 各人物分别知道、误信或隐瞒什么？
6. 读者领先、同步还是落后？
7. 场景主调是什么，若转调，铰链是什么？
8. 哪件物品或哪个称谓会改变状态？
9. 人物必须作出什么选择？
10. 结尾哪项状态已不同于开头？

答不清时先补骨架，不润色。

### 第二遍：让人物与语言落地

按当前场景选择需要的手法：

- 视角从外部动作经感知进入短促判断，再回到行动；
- 对白服从人物知识、关系和目的；
- 情感通过人物专属的三种以内通道显影；
- 文化材料进入规则、能力、冲突或机关；
- 长句按意义语块展开，连接词各有实际功能；
- 武打交代目标、空间、受力、判断和结果；
- 声音安排长短、轻重、复现、破拍与收音。

### 第三遍：清除伪腔与穿帮

重点删除或修正：

- 无功能的古词、成语、四字格和说书套语；
- 无锚点跳心和作者提前泄密；
- 所有人相同的机锋、悲伤、愤怒与口头禅；
- 与行动无关的典故、风物和历史说明；
- 招式目录式武打；
- 随机笑点与没有铰链的情绪切换；
- 物件瞬移、自动修复和新增属性；
- 随机古风专名和一次倾倒全部名号；
- 已经落地后仍继续翻译情感或主题的解释尾巴。

## 七、不同任务怎样调用

### 1. 构思故事

```text
读取当前 `premise.md` 和已有世界设定，给我三个因果方向不同的长篇方案。每个方案说明主角欲望、冲突义务、关键选择链、不可逆后果和结局代价。先讨论，不更新项目。
```

### 2. 塑造人物

```text
为【人物】建立人物系统。重点检查他的稳定天性如何同时制造能力与代价，以及知识盲点、关系语域、情感面具和关键选择。不要先写人物小传；先给结构方案。
```

### 3. 规划秘密或误会

```text
设计【秘密／误会】的信息结构。分别列出后台真相、真实证据、每个人物的解释、读者位置、线索变义、揭示阶梯和揭示后的行动后果，并更新知识账本。
```

### 4. 写人物对白

```text
重写【场景】对白。保持事实和结果不变，先标明每句话的说话目的、知识权限与关系语域；让删去人名后仍能从注意力、逻辑和策略分辨主要人物。
```

### 5. 写情感戏

```text
写【关系转折】场景。明确人物为何不能直说，从身体、称谓、关系动作、物件、对白和短心语中最多选择三个主要通道，让旁人产生识别或误读，并把情绪落到一个有代价的选择上。
```

### 6. 写武打或追逐

```text
写【武打／追逐】。优先交代双方目标、地形、距离、身体限制、受力与控制权变化；招式名只作地标。每一轮攻防都要改变空间、判断、关系或任务局势。
```

### 7. 加入文化材料

```text
为【场景】设计三种文化织入方案，分别通过社会规则、人物知识或情节机关发挥作用。已有素材库不是白名单，可以提出库外候选；请区分待核验内容、史实、争议、传说、文学表达与艺术加工，不写百科段。核验并确认采用后建立素材卡，再登记到正式清单。
```

### 8. 设计叙事物件

```text
设计【物件】的生命周期：现实用途、固定特征、能力与限制、权属分离、转手、状态变化、误读、重现、回收和退场。最终回收必须同时依赖既有物理规则、关系历史和人物主动选择。
```

### 9. 设计名称

```text
为【人物／门派／武学／器物／地点／章节】设计名称。先从命名者、生活经验、动作机制和语义场生成不同来源的方案，再做可呼喊、相邻碰撞和阵营交换测试；不要随机拼接古风高频字。
```

### 10. 改善诵读感

```text
对【段落】做朗读层面的改写。保留事实与人物声口，按意义切分语块，标出主要重音，检查连接词、长短变化、复现、句尾与收音。先给改写稿，再说明三处最关键调整。
```

### 11. 只诊断，不改写

```text
诊断【章节／段落】，不要改写。按“症状—文本证据—影响—可执行修法”输出，并区分故事结构、视角信息、人物关系和语言节奏，按修改收益排序。
```

## 八、项目文件怎样协同

| 文件 | 它回答的问题 | 何时更新 |
|---|---|---|
| `premise.md` | 这是什么故事，核心价值冲突是什么 | 核心承诺或主题问题真正改变时 |
| `story-outline.md` | 全书选择链、阶段后果与伏笔怎样推进 | 总纲确认、篇章方向改变或伏笔回收时 |
| `world.md` | 社会、历史、地理和武学规则是什么 | 新规则成为作品事实时 |
| `characters/` | 人物怎样欲求、判断、说话、动情和选择 | 人物系统确立或发生长期变化时 |
| `relationships.md` | 人与人当前怎样相互定义与欠债 | 关系、称谓、承诺或信任变化时 |
| `timeline.md` | 事情何时何地发生，行程伤势是否连续 | 每章结束及重要转场后 |
| `knowledge-and-beliefs.md` | 真相是什么，谁知道、怀疑、误信或隐瞒 | 线索、秘密、误会或揭示发生变化时 |
| `objects-and-clues.md` | 重要物件在哪里、归谁、怎样变化和回收 | 转手、损坏、污染、修补、失效或变义时 |
| `naming-system.md` | 专名从哪里来、由谁使用、怎样构成网络 | 新增长期专名、异名或称谓变义时 |
| `materials/candidates.md` | 有哪些库外文化候选仍待核验或决定 | 模型、用户或搜索提出新候选时 |
| `materials/` 素材卡 | 某项材料的来源、边界、感官细节与叙事用途是什么 | 开始核验、改编或计划使用该材料时 |
| `materials/source-register.md` | 项目查阅过哪些来源，怎样定位 | 新增书籍、论文、方志或可靠网页时 |
| `reference-manifest.md` | 哪些文化材料实际进入作品，可信度如何 | 素材被确认采用时 |
| `chapter-plans/` | 当前章承担什么任务，怎样结束 | 每章开写前，正文重大偏离后补记 |
| `drafts/` | 已确认的正文版本 | 正文创作或修订完成时 |

同一变化可能需要同步多份文件。例如信物被偷走：

```text
objects-and-clues.md：位置、持有人、状态
knowledge-and-beliefs.md：谁知道或误以为谁拿着
timeline.md：何时何地转手
relationships.md：偷盗是否破坏信任
story-outline.md：若它改变长期主线或回收计划
```

## 九、高质量请求的写法

一个稳定的请求通常包含五部分：

```text
角色与项目：使用哪个 skill，以哪个目录为项目
当前任务：这一次只解决什么
必要上下文：指定章节、人物、事实与不可改变项
创作约束：重点检查哪些层面，哪些内容不要做
交付与同步：要正文、方案还是诊断，是否更新项目文件
```

通用模板：

```text
使用 $guige-wuxia-writing，以当前目录为小说项目。

当前任务：完成【一项具体任务】。
必要上下文：读取【章节计划／人物／相关账本】；【这些事实】不可改变。
重点要求：关注【目标、阻力、视角、声口、情感、信息或节奏中的一至三项】。
不要做：不要【提前揭示／新增设定／改变结果／写成百科／堆古词】。
交付方式：先给【方案／正文／诊断】；【确认后／完成后】同步相关项目文件，并列出更新摘要。
```

最值得明确的四句话是：

```text
先讨论，不要写正文。
这些事实和结果不可改变。
只诊断，不要擅自改写。
把已确认的变化同步回项目文件。
```

## 十、推荐的检查与复盘节奏

### 每场结束

- 目标是否改变；
- 人物是否作出选择；
- 信息、关系或风险是否至少变化一项；
- 结尾是否落在可见结果而非解释上。

### 每章结束

- 回放时间、行程、伤势和物件；
- 更新人物认知、关系和称谓；
- 关闭或实质推进至少一个问题；
- 检查下一章承接的具体不稳定状态。

### 每三至五章

- 核对主要人物是否仍由自身天性作选择；
- 检查误判是否公平、线索是否有阶段答案；
- 检查轻松段与高压段是否都在推进故事；
- 召回久未出现的重要物件、承诺和关系债务；
- 检查专名密度、阵营区分和章名焦距；
- 朗读若干关键段，清理等长语块与抽象句尾。

### 每个篇章结束

- 比较开局与结尾的人物、关系、知识和权力状态；
- 确认变化是否不可逆，而非恢复原状；
- 清算已到期的伏笔、物件与承诺；
- 让下一篇章由本篇后果自然启动。

## 十一、常见误用

### 1. 一次要求写完整部长篇

问题：AI 无法在单轮中稳定维护人物知识、伤势、物件与伏笔。

修正：先确定核心和总纲，再逐章规划、逐场写作、章后同步。

### 2. 只说“写得更像传统武侠”

问题：模型容易转向古词、四字格与套语堆积。

修正：指定真正需要的机制，如“外部动作入心再返回”“人物声口差异”“意义语块和朗读收音”。

### 3. 每次把所有技巧都打开

问题：段落同时塞入典故、物件、谜团、机锋、情感和声律，显得刻意。

修正：每场只选择服务当前任务的主机制，其余保持自然。

### 4. 未确认方案直接写入项目

问题：备选设定会与正式设定混杂。

修正：讨论时禁止回写；明确采用某个方案后再更新。

### 5. 正文写完不做同步

问题：数章后出现人物知识穿帮、物件瞬移、伤势复原和称谓倒退。

修正：把“章后状态同步”视为章节完成定义的一部分。

### 6. 用模板驱动故事

问题：为了填满表格强造物件、秘密、诙谐和命名变化。

修正：无变化就写“无”；模板只追踪真正影响故事的内容。

### 7. 用润色掩盖结构问题

问题：句子更漂亮，场景仍然没有目标、选择和后果。

修正：先诊断第一遍的场景骨架，再处理第二遍语言。

### 8. 接受 AI 新增的未经核对史实

问题：传说、文学表达和史实容易被混写。

修正：先放入 `materials/candidates.md` 并标为待核验；核验后建立素材卡，确认采用时再登记到 `reference-manifest.md`。素材库之外仍可继续提出候选。

### 9. 反复无边界润色

问题：人物声口被磨平，文本越来越华丽却越来越不像人物。

修正：每轮只解决一类问题，并明确保留事实、动机、结果和人物语言边界。

## 十二、最短可行工作流

如果暂时不想管理复杂流程，只记住下面四步：

### 1. 开始项目

```text
使用 $guige-wuxia-writing，以当前目录为小说项目。一次只问我一个问题，帮我确定故事核心；确认后更新项目文件。
```

### 2. 规划下一章

```text
读取当前项目，规划下一章的目标、阻力、关键选择、信息与关系变化、章末不可逆状态；保存章节计划。
```

### 3. 写本章

```text
根据章节计划和相关人物状态逐场创作本章。保持视角、知识边界、声口和连续性，正文完成后做一次伪腔清理。
```

### 4. 同步状态

```text
回放本章，把人物认知、关系称谓、时间伤势、物件状态、专名、伏笔和问题栈的实际变化同步回项目档案。
```

一句话总结：

> 先用人物选择建立因果，再用项目账本保持长期连续，最后用视角、声口、语块与声音把故事写得清楚、鲜活而可诵读。
